# Reflection and replay evidence

A reflection quotes at most three reliably attributed player events. The server supplies the original expression or action summary, feedback and effects from the same turn, and the event reference. Advice remains an alternative for the player, with an explicit possible cost; it does not undo completed work or declare forgiveness.

Each new reflection node can name the closest saved replay point whose entire event history is a verified prefix before that expression. Empty, divergent, missing and later histories are rejected. The server selects the snapshot; model output cannot select or replace it. The UI displays the actual start (for example, the beginning of act three), not a claim that every expression has an exact snapshot. Creating the branch preserves the original save. Old artifacts without replay metadata retain their facts and general replay controls. Read-only revisions explain why branching is unavailable.

The ending, reflection panel, share preview, copied text and PNG use “本局表达倾向”. Existing fact opt-ins and private-dialogue exclusions are retained. Failed/unknown generation retains factual records and usable controls instead of an endless spinner. No schema migration or rewrite of old events is required; new jobs use prompt version 7.

Validation includes history-prefix selection, persisted reflection-to-snapshot/branch integration, event readback/retry, missing snapshots, read-only saves, failed/unknown artifacts, and Mock browser replay with original-save preservation. Real-model evaluation and target-player observation of the alternative/cost and replay entry remain unperformed; button availability alone is not evidence of engagement.
