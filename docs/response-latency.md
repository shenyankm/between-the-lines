# NPC 对话响应与本地完整试玩

V3 把剧情操作和语言生成分开。服务端先用当前角色、幕次、玩家本轮原文和可用行动目录判断意图；明确操作仍调用原有规则事务，重大决定仍生成待确认提议，缺少表单内容时不会补造参数。AI 随后只根据角色可见事实和历史生成对白，使用一个没有工具的 LangGraph/LangChain agent，避免重复查询或重复操作。旧版 DeepAgents 工具路径保留用于兼容与验证。

世界观、角色性格、当前规则事实和最多 12 条可见历史仍进入提示词。角色模型没有权限读取其他人的私聊、改变存档或凭空宣布审批完成。V3 普通对白只需要一次模型生成；精确的材料/审核/支持指令通过原规则直接反馈，不调用模型。未知、引用、否定、混合指令不走这个快捷路径。

OpenAI Responses 适配器只把带有明确 `final_answer` 阶段的文字增量发给客户端；思考、工具参数和中间说明不进入预览。不提供该阶段的适配器仍等待完整终态文本。浏览器收到的是不断更新的全文快照，不能把最后一帧重复拼接。断线不会取消已接受的服务端回合；失败的半截预览会清除，不写入历史。

参考：[OpenAI 流式响应文档](https://developers.openai.com/api/docs/guides/streaming-responses)。当前 GPT6 保持 `low` 推理；[模型支持参数](https://developers.openai.com/api/docs/models/gpt-6-astra)不包含 `none`，不能靠发送不支持的参数强行关闭推理。代码优化不能保证第三方网关没有排队、超时或连接失败。

模型客户端在应用生命周期内复用连接；每轮仍有独立的请求/模型/工具预算，角色对话和 checkpoint namespace 不共享。后台结局/复盘生成、事实校验、费用和令牌统计保留。

## 模型配置与实测边界

`OPENAI_REASONING_EFFORT` 默认是 `low`。GPT6 配置成 `none` 时后端拒绝启动，避免发送必定不受支持的参数。[GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) 官方支持 `none`，但第三方网关的实际表现仍需另测；更改 `OPENAI_MODEL` 和推理选项后必须重启后端。

2026-09-14，本地浏览器通过 OpenAI Next 网关测试相同的两句第一幕对白。以下只是少量现场样本，不能代表平均值或稳定延迟：

| 路径 | 首次可见文字 | 整轮完成 | 模型调用 |
| --- | --- | --- | --- |
| 修复前 GPT6 | 舞台未显示新回答 | 11.4 / 22.0 秒 | 1 / 2 |
| 一次生成后的 GPT6、low | 25.0 / 16.7 秒 | 27.1 / 19.0 秒 | 1 / 1 |
| 同路径 GPT-5.6 Luna、low | 15.0 / 9.7 秒 | 18.0 / 11.4 秒 | 1 / 1 |
| 精确材料要求指令，桌面 / 手机 | 完成后立即可见 | 0.076 / 0.078 秒 | 0 / 0 |

普通对白的输入令牌从约 3958 / 7701 降到 1747 / 1935；两次生成收敛到一次，但 GPT6 首字仍有明显网关等待，不能声称普通聊天已稳定提速。Luna 关闭推理的两轮游戏对比出现一轮网关 APIError，未通过完整测试，因此当前本地试玩保留 GPT6 low；代码没有自动切换或以预设对白伪装 AI 成功。

最终本地验证：后端 367 项通过、覆盖率 83.83%；前端 286 项通过、分支覆盖率 91.33%、API 客户端 100%；完整桌面/手机回归 104 项通过、2 项显式跳过。一次生成调整后重点复测 32 项，其中访客用例触发测试库注册限流，清理该库限流记录后对应 6 项全通过。真实 GPT6 对话和结局冒烟通过。类型、格式、构建和 API 契约检查通过。

## 本地完整试玩

在本地后端环境设置 `GUEST_FULL_STORY_ENABLED=true` 并重启 API，可让原访客账号和同一存档继续第二、三幕。首页显示「立即试玩 · 完整故事」，不会创建新身份来绕过限制；访客 AI 次数和有效期仍保留。生产环境拒绝启用这个开关，正式知乎登录和绑定逻辑不变。

## 验证要点

- `tests/test_reply_streaming.py`：公开增量、失败清理、连接复用、调用预算和精确操作的权限边界。
- `tests/test_runtime.py`：NPC 回复记录实际场景；完整试玩保留访客身份。
- `e2e/reply-display.spec.ts`：本轮新回答必须实际出现在主舞台，刷新后仍可见。
- `e2e/gpt6-live.spec.ts`：明确启用的真实 GPT6 冒烟也检查页面可见文本，不能只凭回答入库判断成功。
- `src/sendTurn.test.ts`：完成前已收到文字、快照替换、错误角色帧拒绝；接口客户端覆盖率仍要求 100%。
