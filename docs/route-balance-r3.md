# Route balance in content revision 3

New saves use revision 3. Revision 1 stays read-only; revision 2 remains playable using its original scoring. Both playable revisions use the same authored workplace scenes. No historical event is rewritten, and branches retain their source revision. Save capacity, AI jobs, story reads and action availability include both playable revisions.

| Context and choice | Immediate effect | Remaining cost or obligation |
| --- | --- | --- |
| Valid original materials; copy and resubmit | A new material version; no numeric reward | Approval and delivery still required |
| Valid original materials; ask Li to correct an unjustified return | Credit +10, pressure -5 once; correction recorded | Li must still approve; Zhang owns project coordination |
| Missing actual evidence; supplement it | Credit +10, pressure -5 once | Cannot skip evidence or financial approval; urgent requests require urgency evidence |
| Publicly confront with verified rumor records or a successful procurement recheck | No credit deduction; rumination +5, heat +20 once | Public attention remains a cost; no automatic clarification or relationship repair |
| Publicly confront without that evidence | Original credit -5, rumination +10, heat +20, once | Public attention and unsupported conflict remain costs |
| Defer responding | Pressure -5, rumination +5 once | Boundary and work issues remain unresolved; no agreement or forgiveness inferred |

Boundary, confrontation and restraint can be expressed again in another act, but their numeric effect is awarded only once per playthrough in revision 3. Procurement material/correction rewards share one scoring key, preventing order-based reward duplication. Rest and concrete support continue to require recorded applications and actual arrangements.

The first authored procurement request is ordinary. The material form explicitly allows changing the next submission to urgent, which requires an urgency attachment. Extra attachments on an ordinary request do not silently convert it into urgent procurement. Approval validates the persisted application type.

Deterministic tests compare old/new revisions, both procurement routes, actual missing urgent evidence, role permissions, evidence-sensitive confrontation, and repetition across acts. Mock browser checks compare the visible receipt and material validation. These are design/rule checks, not evidence that target players prefer the balance; user comparison remains pending.
